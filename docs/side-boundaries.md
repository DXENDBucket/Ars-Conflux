# 客户端／服务端边界排查

日期：2026-10-11。版本：Ars Conflux 0.1.7、Iron & Nouveau 0.17.6；Goety & Nouveau 0.1.0-dev.3 无需改动。

## 起因

Iron & Nouveau 0.16.2 的用户日志显示：客户端接收实体生成包后，转换监听器查询 Ars 的施法者，发生 `ClientLevel cannot be cast to ServerLevel`。

检查本地 Ars 5.13.1、测试目录中的 5.13.3 及 Forge Ars 4：`SpellContext.getUnwrappedCaster()` 在没有实体施法者时，会把上下文世界转为 `ServerLevel`，再创建 Ars 原生假玩家。因此，“先查询 caster、再检查 caster 的世界”不能防止异常。缺失世界的未绑定上下文也不能走这条回退。

0.1.6／Iron 0.17.5 已修复实体加入时的直接入口。这次继续审查其他调用链。

## 处理结果

| 位置 | 边界及处理 |
| --- | --- |
| 公共 `CastContexts.resolve` | 改用安全的 `ArsSpellAccess.caster`；没有服务端世界时不请求假玩家。 |
| Forge 起手支付 | 原来查询 caster 后才检查世界；现在直接读取上下文世界，确认服务端后支付。 |
| 散射预算、原生 Ars 触发计费 | 仅在服务端启动事务；客户端继续原生回调。无法报价的载荷不调用空报价对象。 |
| Iron 预设工具作用域、附魔剑触发、冷却归属检查 | 全部使用同一安全读取 API；没有 caster 时不建立工具授权。 |
| Iron 施法前检查、效果魔符解析 | 在进入工具作用域和查询权限之前检查服务端。缺少 caster 的首次费用返回未知。 |
| Iron 持续效果子实体发射 | 在强转父实体世界前检查 `ServerLevel`，客户端保留原生行为。 |
| Iron 租约中的 owner UUID | 脉冲及发射先检查 UUID 是否存在；损坏数据不能引起 UUID 读取异常或产生无主效果。 |
| Goety 原生替换、命中、客户端运动 | 替换和命中已限定服务端；客户端仅处理同步状态和外观。公共上下文获得本次 Core 修复。 |
| Iron／Goety 的 Forge 开发启动 | 源目录运行没有读取 Core 发行包的 manifest，导致 Core Mixin 未加载；两个开发构建显式传入 Core 的配置。发行包已有独立声明。 |

剩余的 Iron `ServerPlayer` 强转分别由冷却适用检查、采矿权限检查和 Mana 来源选择保证；持续效果内部的 `ServerLevel` 强转只处理服务端加入的实体或已通过服务端检查的调用。

检查了两端的网络注册与接收：客户端包在主线程处理，视觉处理读取客户端世界、维度及实体身份，没有查询服务器施法者。没有为这些已具备边界的路径增加重复支付或新的协议。

## 验证范围

两端各通过 6 项 `irons_nouveau_shared` 与 `irons_nouveau_context` 定向 GameTest，不运行完整回归套件。新增用例使用缺失世界的真实 Ars 上下文，并让不安全施法者查询直接抛断言，验证安全读取、预设工具作用域、未知费用、散射预览、施法前回调、原生回调及损坏租约；同时检查服务端装置仍使用 Ars 原生假玩家。既有用例检查封存工具存储和施法归属、代理及持续执行。Forge 日志确认实际加载 `SpellContextAccess`、起手支付及转换等 Core Mixin。

修正 Goety 的 Forge 开发启动后，其 6 项魂魄箭定向测试也通过，覆盖原生命中／接续、散射和资源、持续轨迹及原生转向；本次没有重复 NeoForge 的 Goety 完整验证。

这是服务端定向回归和代码审查，没有启动真实 `ClientLevel` 或重放客户端生成包，也没有完成客户端画面／多人实机验证。
