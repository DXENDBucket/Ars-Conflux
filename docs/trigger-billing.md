# 原版 Ars 的可选触发计费

世界配置：`serverconfig/ars_conflux-server.toml`。整合包新世界模板可放在 `defaultconfigs/ars_conflux-server.toml`，专用服务器决定规则。

```toml
[ars_trigger_billing]
enabled = false
```

默认关闭，使用 Ars 原有的报价、施放资格和起手扣款。打开后仅适配 `ars_nouveau` 命名空间下的原版效果，不给其他附属自动改价，也不覆盖 `TriggerPaidGlyph` 提供者自己的事务。

## 费用

起手 Cast Method 及其书写增强仍在起手扣费；效果及紧随其后的书写增强组成一个费用组，在原生 `AbstractEffect.onResolve` 入口支付。附属效果保留原来的起手费用。装备自动附加的增强沿用原有行为，不冒充玩家书写的付费魔符。

费用组遵循原版的 `getCastingCost()` 和 `getCostForPart()`。原版装备减耗按各组费用比例分配，整数余数通过累计份额分摊，一轮无分支编排不会因为分组获得多次完整的装备减耗。每个报价继续经过 Ars 的费用事件，第三方事件处理器仍可修改该次价格；按整次施法收取固定附加费用的处理器需要识别拆分报价。

触发付款通过公共 `ResourceTransactions` 预留，再走该报价 resolver 的原生支付方法；NeoForge 使用 Ars 5 的 Pre/Post 费用阶段，Forge 使用 Ars 4 的单个阶段。内部报价冻结最终价格，效果不会在执行中途重新改变自己的费用。Ars ’n Spells 的可用原生支付桥继续参与报价，并在结束后释放临时报价；Core 不硬依赖它或 Iron。

Core 0.1.5 的可选 Hex-Ars Linker 适配保留原生 Mana 倍率，包括每次触发的报价与实际扣款。指定位置／目标入口省略的人工形态费用只在起手省略，不会再次从命中效果中减去。Linker 的额外媒质费用仍按完整原生 Ars 术式计算，不因移到触发时付款而漏报；提供者自己的首次费用不自动套用这个 Ars 倍率。详见 [Hex 资源边界与验证](hex-ars-linker.md)。

## 嵌套与持续载体

`自身 → 环绕 → 环绕 → 伤害` 不只在施放时计算两个环绕。第一次创建外层球体支付一组环绕费用，每个外层球体触发创建内层环绕时再支付一组。余量只能支撑一次内层创建时，其他分支不再创建新球体。

重复命中、环绕、回响或延迟后续编排只要重新进入原生 resolver，均再次检查和支付相应效果费用。余额不足停止这一次分支，其他已存在的载体保留原生生命周期。计费不是独立的实体数量上限；零费用效果和创造施法仍免费。

## 执行与失败

- 未命中的弹射物只支付起手费用。
- 被原版解析前事件或目标能力拦截、没有进入效果执行的调用不收费。
- 余额不足不会执行该效果，并停止当前上下文的后续编排。
- 原版效果正常返回即为付费尝试，即使目标不适用而没有实际改变世界；其 `void` 接口没有统一的“生效成功”信号。
- 抛异常不提交本次扣款，但不回滚已经发生的世界变化；成功的嵌套事务保留自己的扣款。
- 效果内部对多个目标生效、生成状态效果后自动持续，仍算一次调用；不对这些内部动作逐个收费。

只自动适配生物的 `LivingCaster`，包括玩家和使用同类资源池的生物。创造模式免费。魔源炮塔等非生物包装器保持原生魔源规则，避免将已经起手消耗的魔源再次收取。专门设备可以使用 Core 的资源账户 API 实现自己的触发收费。

计费开关随施法保存到上下文并传播给子上下文，配置重载只影响新施法。该实现不推断某个原版效果的伤害、目标有效性或内部脉冲；需要更细语义时应另做效果适配。
