# Ars Zero 2.0.2 / Conflux 0.1.33

## 范围与版本

NeoForge 1.21.1 的可选适配，针对实际发布的 Ars Zero **2.0.2**（CurseForge 文件 8703997）。原 JAR SHA-256：`4682b08eb150672666d82370baa8c64a9e543989b5af6f5c164834e02fcf741c`。

Zero 不成为 Core 的必需依赖，编译依赖不打进发行包。所有接线位于 NeoForge 目录；Forge 1.20.1 本次只共享通用 `ActiveCasts.Sequence` API，没有移植 Zero。检测到其他 Zero 版本时不应用本次可选 Mixin，需要重新核对发布字节码后扩展支持。

不替换或修改官方 Zero JAR，不复制其代码、贴图或声音。原生效果、实体、生命周期、声音、粒子与移动计算仍由 Zero 执行。此前针对公开源码的修复分支仅作对照：该源码基于 2.0.0-beta3，不能整体重编译覆盖 2.0.2。

## 主动使用

法杖和施法头环的一次按住视为一次主动使用。开始、持续、结束三个已声明编排共同参与准备和起手冷却查询，采用现有的最长／累加吟唱规则、提供者 HUD 与移动限制。

第一轮真正获得 resolver 释放确认时，为三个声明编排提交一次提供者冷却；尚未成功发射便取消不会产生冷却。开始阶段为空时，持续或结束阶段可以成为第一次确认。即使随后没有执行结束阶段，整个声明计划的起手冷却也已经提交。

持续与结束阶段不重新吟唱，不被本次使用刚提交的起手冷却拦截。每次效果的实际费用、目标资格、原生特殊冷却和原生持续机制仍逐次执行，不预付无限次持续触发的费用。

准备期间松开、换物品、修改编排、取下头环、死亡、离线、换维度、卸载世界会取消；头环不要求主手一直拿着一个无关物品。持续中修改编排会结束该使用，不能偷偷改成未准备的新法术。

```toml
# ars_conflux-server.toml
[zero]
chanting = true
cooldowns = true
```

## 光束与资源

保留 Zero 光束本身的费用。后续编排中，已经由 `TriggerPaidGlyph` 自行付费的组，不再计入 Zero 的附加重复报价。启用 `ars_trigger_billing.enabled` 时，交给 Core 按实际触发扣费的原版 Ars 效果组也被排除。组内书写增强随该组一起处理。

未接入触发付费的 Zero／其他附属效果继续保留 Zero 原来的报价倍率。创造模式不再因这条附加报价路径扣除魔力。没有把光束内部所有行为改成另一套效果模拟。

## 原生修正

- BEGIN 自动捕获方块之前，以及 Post 回退读取世界方块时，拒绝无法安全搬运的状态，包括方块实体、不可破坏方块、非活塞可推动状态及 `c:relocation_not_supported`。避免先删掉容器再尝试保存其数据。保留 2.0.2 已有领地、维度与施法者隔离逻辑。
- 修正 Select 在发布版本中反向的世界高度判断。
- 汇流初始魔源按当前书写出现及其增强计算；分支共用一次施法的总预算。魔源驱动的返还按实际已付报价缩放并封顶，未知装置入口不凭事后的可变报价产生初始魔源。后续真实搬运仍使用原生充能实体。
- Zero 多阶段炮塔在付款后记录该轮实际报价；充能原点使用炮塔位置，避免发射口假玩家坐标影响魔源来源。

## 上一轮结果

Temporal Context 改成读取**上一轮实际执行的输出**，而不是永远读取 BEGIN：第一次持续读取 BEGIN，后续持续读取上一轮持续，结束读取最后一轮实际输出。没有执行过持续时，结束读取 BEGIN。执行了但没有产生结果的轮次不会回退到初始目标。

每轮输入为独立快照，输出另存；旧弹射物／延迟回调不能覆盖新一轮选点。实体／方块命中和 Beam、Voxel、Geometry、Select、Convergence 产生的对象均纳入此边界，保留原生效果与选点特效。逐目标执行传递单独输入，避免多个目标之间重复遍历和锚点偏移漂移。

交互控制仍读取当前选择。物理恢复另行追踪所有本次锚定对象和捕获方块组，避免切换选择后漏掉旧对象。恢复后只有最后选择的结果进入下一阶段；普通实体恢复锚定前的重力与碰撞设置。

```toml
# ars_conflux-startup.toml；重启生效
[compatibility]
enable_zero_compatibility = true   # 主动使用与光束计费
enable_zero_native_fixes = true    # 方块安全、高度判断、汇流核算
zero_previous_phase_targets = true
```

三个开关独立。未安装 Zero 或版本未匹配时均不接线；没有改动一般 Ars 法术的起手流程。

## 验证边界

本批采用低内存编译、纯 Java 状态／预算测试，以及直接读取官方 JAR 的注入目标检查，不启动客户端或测试服务器。静态检查核对方法、调用点和描述符，不等于验证加载器实际应用 Mixin 或画面表现。

人工检查建议收拢到一次游戏中：法杖与头环提前松开／换维度、开始为空的持续编排、重复 Iron／Goety 魔符、光束空蓝停止、Select 搬运安全、上一轮目标与锚定结束恢复。客户端 HUD、粒子、多人同步和实际组合行为尚需人工验证；不把原有上游测试里的跳过用例算作已通过。
