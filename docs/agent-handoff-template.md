# 附属任务交接模板

这份模板用于实际交接，不是需要每次提交的测试清单。填入事实即可，删除不相关项。

## 范围

- 用户目标：
- 负责的附属 / 工作树绝对路径 / 分支：
- 允许修改的目录：
- 不在本次范围内的内容：
- Conflux 固定完整提交 / 构建副本路径：
- 目标 MC / 加载器 / 本体版本 / JDK：
- 可写的测试目录；共享实例由谁管理：

## 已完成与下一步

- 最终实现和对应文件：
- 本体机制核对依据（发布 JAR、源码提交、关键入口）：
- 已知问题或明确保留的差异：
- 下一步可直接执行的工作：
- 如需要 Core API 改动：具体需求、复现和临时不依赖它的工作：

## 验证证据

- 实际命令、工作目录、平台、可选联动参数：
- 结果、测试数量、日志/报告位置：
- 客户端人工验证了什么；没验证什么：
- 固定 Core 副本 `git status --porcelain --untracked-files=no` 的结果：
- 原模组常规行为是否受影响；有何证据：

## 交付

- 版本 / 提交：
- 最终 JAR 绝对路径 / SHA-256：
- 许可与资源打包边界：
- 是否已经部署、部署到哪里、共同环境是否验证：
- 其他 agent 正在做什么、有哪些共享资源不能触碰：

## 可直接发给下一个 agent 的开场

> 在指定的附属工作树继续上述任务。先读 `AGENTS.md` 和共享开发流程，核对 Git 状态、固定 Core 提交和测试目录。不要修改 Conflux 的受版本控制文件，不要部署到共享实例。依据已有验证证据继续推进，只对新修改或明确疑点补必要验证；完成后交付提交、JAR、哈希与剩余人工验证项。
