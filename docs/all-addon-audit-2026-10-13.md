## 2. 已确认的缺口

### A01 · P1 · Iron 的局部付款账户会流入后续附属

**源码确认，尚未运行最小复现。**

Iron `common/src/main/java/dev/ironsnouveau/glyph/AbstractBridgeGlyph.java:82–90` 取得当前上下文后，用 `mana.account()` 替换账户，并将替换后的 frame 通过 `CastContexts.bind` 写回原 `SpellContext`。这发生在权限检查、实际执行之前。`casting/NativeCasting.java:117–128` 的弹射物及命中续接同样附带本次 Iron 账户。

Core `api/context/CastContexts.java:25–40` 会把这个账户作为链路附件继承。Aquamirae `AquamiraeCosts.java:16–20` 和 Mowzie `MowzieGlyph.java:53–58` 优先接受 `frame.account()`；BOMD 与 Cataclysm 的费用则重新选择 Ars Mana。

因此在独立魔力池环境中，编排顺序可能决定海灵／Mowzie 魔符扣 Ars Mana 还是 Iron Mana。即使前面的 Iron 效果因目标不适用而失败，附件也已被修改。默认都使用同一个池的整合包容易掩盖这一问题。

Goety 已有可参照的处理：`GoetyEffectGlyph.java:69–84` 只把原链路账户绑定回去，将本次灵魂账户用于局部执行；`GoetyNativeProjectileCasting.java:121–133` 在续接时恢复 `inheritedAccount`。

**修复方向：** 明确区分入口显式提供的链路付款账户与提供者本次选择的默认账户。Iron 效果和弹射物不得把后者永久发布给后续提供者；仍保留外部 API 显式代付的能力。不能简单删除所有账户继承。

**最小验收：** 分离 Ars／Iron 魔力池，执行“自身 → 可成功的 Iron 增益 → 海灵增益”和“Iron 替换弹射物 → Mowzie 效果”，交换顺序；再测前段 Iron 失败以及显式自定义账户。每种效果只扣其约定的池，预估与实际首次扣款一致。

### A02 · P1 · Hex Linker 的直接入口没有主动吟唱／冷却事务

**源码及 Neo 实际 JAR 字节码确认。既有文档保留过此边界，需要补完整入口政策。**

Linker `OpCastFromPlayer$Action.cast` 调用 `SpellCaster.castSpell`，经过 Core `ActiveCasterChantMixin:20–25`。`OpShootCast$Action.cast` 则自行检查／扣除 Ars Mana，再创建弹射物；`OpTouchCast$Action.cast` 直接调用 resolver 的 `onCastOnEntity`／`onCastOnBlock`。

Core `ActiveCasts.java:126–135` 在没有当前主动事务时放行派发，且不登记主动释放。这对已经发出的弹射物、回响和持续触发是正确的，但 Linker 的新主动操作也走到了这个分支。`OptionalHexResolverMixin` 目前只适配来源和报价。

**影响：** 同一编排换用 Linker 操作后，可以没有吟唱等待，也不检查／登记相同的主动冷却。不能据此声称免费：Ars、提供者触发费用及 Hex 媒质各自仍有扣费入口。

**修复方向：** 在 Core 的可选 Linker 入口明确建立主动使用边界，区分新操作与已有法术的回调。如何延后 Ars 释放、是否需要保存选点、Hex 后续指令是否继续，需明确约定；不要让整个 Hex VM 隐式阻塞，也不要在所有 resolver 命中上补全局冷却。

**最小验收：** 同一带冷却魔符分别从法术书、Linker 普通施法、指定点、指定实体释放；检查冷却中拒绝、成功登记、吟唱取消、媒质／Mana 无重复扣款，以及回调不会重新吟唱。Forge 的对应实际操作另行复核，不能只复用 Neo 字节码结论。

### A03 · P1 · 部分执行授权没有使用 Core 的友军关系

**源码确认。**

- BOMD `casting/GauntletLaser.java:43–50`、`GroundEffects.java:118–120` 只使用自身和双方 `isAlliedTo`。
- Goety `casting/GoetyBreathGeometry.java:26–27` 使用自身及 `MobUtil.areAllies`，多个持续入口统一经过这里；当前项目未登记或读取 Core 的 `Allies` 提供者。
- Core `api/targeting/Allies.java:20–31` 还接受所有者关系和注册的外部关系；`MethodNearbyAllies` 使用此规则选人。Iron 友军动作、灾变新动作、海灵和 Mowzie 已有相应接入。

**影响：** 仅由 Core 外部关系提供者认定的友军能被形态选中，却被 BOMD／Goety 的动作拒绝。Goety 原生召唤关系也不能靠“别人恰好使用 Goety 的判断”自然传播到所有附属。

**修复方向：** 动作执行授权共用 Core 关系，并以原施法者为参照。Goety 特有关系由 Goety 附属向 Core 登记，且回调不得递归调用 `Allies`。普通状态接受者和原生伤害保护另行判断，不把全世界 `isAlliedTo` 替换掉。

**最小验收：** 不加入原版记分板，仅注册临时友军关系，使用周围友军／射线给目标执行激光、吐息；解除关系后持续动作停止。再测原生 Goety 仆从，显式更换 damageOwner 不应授予控制敌人的权限。

### A04 · P1 · BOMD 地潜仍对自身与友军使用不同朝向

**源码确认。** `casting/GroundEffects.java:123` 仅当实体目标正好是施法者时使用 `selected.getLookAngle()`；友军目标走 `direction(context)`（146–150 行），优先取来弹方向，否则取施法者朝目标的向量。

**影响：** 自身地潜沿自身朝向，友军地潜可能沿施法者射来的方向，和当前“实际执行者决定自身动作方向”的约定不一致。

**修复方向：** 实体执行一律取实际执行者朝向；方块选点是否代表移动施法者，作为这项原生位移能力的独立约定保留或明确，不从友军分支推导。

**最小验收：** A 面向东，友军 B 面向北，A 用射线／弹射物命中 B；B 的地潜应使用北向几何。自身同样走一个计算入口。

### A05 · P1 · Mowzie 的位置爆发会给付款者附加身体状态

**源码确认。** `SolarPulses.java:18–27` 对方块或敌方实体选点保留 `host=frame.caster()`、`follow=false`；位置中心本身正确。`entity/SpellSolarPulse.java:47–50` 却不检查 `followsHost`，仍向 `getCaster()` 施加减速，超新星还给予抗性。

**影响：** 在远处位置释放爆发时，付款者被当成实际身体执行者；位置法术也会给付款者带来抗性。问题不在允许敌方位置出现攻击性爆发，而在它同时影响了不在该位置的付款者。

**修复方向：** 区分原生实体需要的所有者引用与实际执行实体；固定位置不附加身体状态、不占用付款者。自身和友军使用同一宿主路径，不能把敌方目标强行变成执行者。

**最小验收：** 方块／敌方位置触发时 A 的移动和状态不变；自身和友军触发时，仅实际宿主获得对应准备期状态。

### A06 · P2 · Mowzie 太阳光束提前结束后减速残留

**源码确认。** `NativeCasts.java:82–84` 一次性给予实际玩家宿主 `activeTicks + warmupTicks + 5` 的缓慢 III；`close`（96 行）仅移除原生实体和 tick permit，没有撤销／到期缩短本次减速。

**影响：** 缺蓝、失去友军关系、主动终止等提前结束路径，光束消失后玩家仍减速到原定时间。

**修复方向：** 使用按执行会话维护的移动限制，或短期刷新并保留原状态。不能在结束时无条件 `removeEffect(SLOWNESS)`，以免删除其他来源的减速。

**最小验收：** 提前结束光束后解除该次限制，同时预先存在的另一份缓慢效果仍正常存在。

### A07 · P2 · Iron 与 Goety 混合吟唱会重复缩放移动输入

**Neo 源码及实际 Iron JAR 字节码确认，客户端手感尚未人工复现。**

Core `ActiveCasts.Pending.sync` 对每个参与提供者发送同一个准备状态。Iron `NativeCastingMovementMixin` 扩大原生 `ClientMagicData.isCasting` 判定；本地 Iron `ClientPlayerEvents.onCalculatePlayerSpeed` 直接把输入乘以 `0.2 + CASTING_MOVESPEED - 1`。

Goety `NativeChantMovementMixin` 在另一个输入监听器后执行 `client/CastingMovement.apply`。非 FullStop、非正在使用物品时再次乘 `0.2`，没有识别 Iron 已经执行了同一准备期限制。若 Iron 有效倍率也是 0.2，最终就成为 0.04。

**修复方向：** Core 可以提供中立的移动限制声明与一次合成入口，取最严格限制／明确的组合策略；附属仍负责读取原生移动属性。复用原生 HUD 不意味着两边独立修改同一输入。实现时不能同时保留原生缩放再额外套合成倍率。

**最小验收：** 纯 Iron、纯 Goety、混合编排，在默认配置、FullStop、原生移速修饰、真实物品使用几种情况比较；只组合一次，取消后恢复。

### A08 · P2 · 冷却拒绝反馈缺少公共格式及选择规则

**源码确认。**

| 附属 | 当前动作栏反馈 | 显式红色 |
| --- | --- | --- |
| Iron | 原生法术名＋冷却提示，无剩余秒数 | 是 |
| Goety | 聚晶／对应物品名＋冷却提示，无剩余秒数 | 是 |
| BOMD | 魔符名＋剩余秒数，1 位小数 | 是 |
| Cataclysm | 魔符名＋剩余秒数，1 位小数 | 否 |
| Aquamirae | 名称＋剩余秒数，1 位小数 | 否 |
| Mowzie | 魔符名＋冷却提示，无剩余秒数 | 否 |

证据是各 `ActiveCastProvider.allowed`：Iron 42–49、Goety 65–74、BOMD 29–37；灾变 `CataclysmActiveCasts` 38–44；海灵 `AquamiraeCooldowns` 49–56；Mowzie `MowzieCooldowns` 32–36。

Core `ActiveCasts.allowed:52` 遇首个拒绝立即返回；提供者按注册 ID 排序。因此混合编排的提示通常由提供者排序和各自扫描顺序决定，不保证显示最后完成冷却的那项。查询过程中直接发消息，也不适合未来给 AI 或预览界面作静默资格查询。

**修复方向：** 中立的结构化拒绝结果（原因、显示名、可选剩余 tick）由 Core 选择和呈现，附属继续使用原生冷却存储。可用剩余时间中优先提示最长者；未知剩余时间应明确处理。保留 Iron／Goety 原生进度显示，不为其他附属强加同样 HUD。

**最小验收：** 同一编排两个附属分别剩 2 秒／10 秒；重复点击不会刷聊天，提示指向真正仍阻塞的项目，创造绕过和关闭冷却后不留下错误提示。

## 3. 必须先定清、不能直接当 bug 修掉的差异

### D01 · 主动释放成功与效果成功不是一回事

各提供者通常在 Core 接收 resolver 成功派发后，为编排中的不同能力登记冷却。弹射物未命中、后续效果目标不适用或资源不足，不一定退回已经开始的主动冷却。Core `ActiveCasts` 的 `Attempt.recipes` 还包含初始编排，不能把它理解成“所有实际成功效果的清单”。

BOMD 地潜是明确的例外：`BomdActiveCastProvider.released` 排除 EARTHDIVE，由 `BomdCooldowns.succeeded` 仅在成功传送后提交。海灵控制光环还会在授予和结束时维护恢复期。它们不是统一规则下偶然写错的几个数字。

建议把“发射冷却”“结果冷却”“结束恢复期”作为提供者可选政策。保持用户此前要求的命中／环绕／回响续接不被主动冷却阻断。无效友军动作不扣该效果的触发费用，**不自动等于**退还原生 Ars 形态起手费或取消整个编排的冷却。

待复现：海灵 `CreatureAuras.start` 内立即调用 `granted`，如果同一同步调用栈又进入另一个主动入口，可能在整次释放结束前拦截后续分支。普通“周围友军”直接调用 `onResolveEffect`，不能仅凭这段代码断言普通多友军已经坏了。

### D02 · 生物、假玩家和死亡重生的冷却政策不同

Iron／Goety 主动冷却检查只作用于真实 ServerPlayer，且默认资源读取也有玩家边界；BOMD、灾变、海灵、Mowzie 的计时适用于一般 LivingEntity。不能为了表面一致给原生怪强加玩家能力字段，也不能默认生物无限免费。

海灵和 Mowzie 在两平台均监听 `PlayerEvent.Clone` 复制冷却。BOMD／灾变的附属冷却只写普通持久数据，当前没有对应 Clone 复制入口。这个差异应确认统一政策并在死亡重生和末地返回实际验证；本轮没有把源码缺少复制等同于已在每个平台实测冷却清零。

建议公开区分“玩家主动入口”“非玩家账户及调度”“自动装置”。整合包 AI 仍属于整合包核心，Core 提供能力而不接管每个怪的原生 AI。

### D03 · 持续能力尚未全面迁移执行锚点和占用类别

Iron 吐息使用实际宿主的 `ExecutionClaim.channel`，位置吐息不占用付款者；灾变体术使用 `action` 和 `startReplacing`。Goety 部分持续能力仍通过 `occupiesCaster=true` 得到旧的非独占 ACTIVITY；BOMD 巨拳激光与 Mowzie 的部分引导未声明相同的显式占用。

这会影响“正在施法”的查询、绑定工具能否开始下一次施法和跨附属打断，但不能把所有持续效果都改成互斥。海灵已明确允许多个友军各自持有同种控制源，继续保留；同一个真实实体的身体动作、持续喷吐、独立位置场各有不同语义。

建议逐能力声明：是否占用身体、是否允许并行、是否允许替换、位置执行是否有意义。优先迁移公共关系和状态清理，避免一次性改变所有组合玩法。

### D04 · 状态接受者、执行宿主、攻击落点应明确区分

Iron 普通目标效果 `Targeting.select(..., harmful=false)` 允许对非友军施加状态；海灵原生状态也保留普通接受目标规则。它们和要求自身／友军承担吐息、位移、动作的授权不同。前次执行锚点审计和海灵 dev.10 文档已明确这点。

Mowzie 超新星／日炎爆发能在敌方位置爆发，是位置攻击的已有设计；A05 要修的是付款者被附加身体状态，不是把攻击落点限制成友军。BOMD 地潜、Mowzie 隧道本质要移动真实实体，不必勉强造出没有实体的位移。

| Cataclysm | Ars Mana、Ars 装备／事件；增强按 `clamp(0.20×基础伤害, 2, 10)` 的可配置步长 | 按 Boss 系列与来源排列；动作可有幻影，位置／实体执行分别明确；整套获取按既有 1–3 次击杀原则 |
| Aquamirae | Ars Mana、已接入的原生弹体成长与 Ars IDamageEffect；增强意义因能力而异 | 原生状态／武器／生物能力；控制动作有独立持续费用和恢复期；已明确取消自定义主动前摇和顶部条 |
| Mowzie | Ars Mana、Ars 装备／事件；伤害增强参考 Harm，地卜体积等用专门增强 | 原生能力与独立适配胶合；部分原生玩家能力仅支持玩家宿主，位置引导尚未支持；当前为私有本地原型 |

这些差异本身不构成重做理由。通用 API 适合统一付款来源、执行角色、失败结果、友军查询、会话清理与显示入口；不适合统一所有召唤、成长公式、原生增益名称或 Boss 整套动作。

具体范围建议各能力按以下字段维护，附属自己持有元数据，不要求 Core 枚举原模组技能：来源入口；魔符类别；实体／位置／方向输入；执行与伤害所有者；原生保留行为；主动冷却及维护费用；继承的后续 Ars 编排；客户端表现；明确未复刻的部分。

## 5. 展示、配方与静态检查结果

本轮在七项目 `common/src/main/resources`、`src/main/resources`、`forge/src/main/resources` 内解析 **478 个 JSON**：没有语法错误或对象重复键。现有中英语言文件键集合对应；跨项目语言键没有发现同键不同值的冲突。该检查不证明动态拼接的键全部存在，也不证明渲染、图标布局或远端客户端显示正常。

## 6. 待运行核验，不在本轮宣称已通过

1. **混编真实扣费**：A01 的分池、顺序交换、失败前段、显式代付；同池余额只足够部分散射时保持 Ars 对称散射。
2. **多源移动状态**：A06／A07 的提前取消及混合吟唱；原生缓慢效果不能被联动错误删除。
3. **命中后续接语义**：海灵回旋武器按原生 hurt 成功续接，碎晶按接触续接，和其他载荷不完全相同。这是已记录设计；需要决定是否保持，再测无敌帧、事件取消、方块碰撞、NEG 再发射和回响。
4. **伤害事件的副作用**：BOMD `GroundEffects.damage:107–114` 忽略 `NativeSpellDamage.hurt` 返回值，仍施加击退／燃烧／缓慢。与部分“伤害取消则副作用也取消”的适配不同；需核对原生语义和 Pre 取消预期，避免无敌帧下本来允许的控制被一并删掉。
5. **短暂视觉与多人跟踪**：按原生弹体、原生区域、光束、动作幻影各抽一个代表，从另一观察者和晚加入跟踪的客户端看生命周期；特别检查原生粒子不等于光束本体、实体消失不等于残留状态清理。
6. **可选组合与平台**：NEG 调态节点／回响、Elemental 再发射、Controle 跨维度、Linker 直接入口。仅对修改影响的组合测试；Forge 独有 Goety 震击和 Neo 独有能力不要求互相复制。
7. **独立安装与原生行为**：涉及 Mixin 或初始化的修复再验证缺少其他附属时加载、专服端侧和原生施法回退。当前“主源码能搜索到钩子”不构成启动通过证据。

## 7. 建议实施顺序与验收边界

### 第一批：结算和明确错误

- 修 A01，先收住提供者局部账户传播；用真实两个魔力池覆盖普通效果及弹射物续接。
- 修 A03／A04：让旧执行授权接受 Core 关系，BOMD 友军地潜用实际宿主朝向。
- 修 A05／A06：位置爆发与身体状态解耦，光束提前结束清理自己的移动限制。
- 同批分别在各附属独立工作树修改；只有确认公共 API 缺口才开 Core 修改，不能给附属增加互相依赖。

### 第二批：公共交互契约

- 设计并接入 A08 的结构化拒绝与冷却显示；共用呈现，不更换原生存储。
- 处理 A07 的多提供者移动限制合成；保留各来源属性，禁止重复应用。
- 为 A02 定义 Linker 新主动操作的异步释放语义，随后覆盖双平台对应操作。
- 明确 D01／D02 中结果冷却、恢复期、生物／假玩家、Clone 的政策，再实施；不能在一次界面统一中悄悄改变它们。

### 第三批：旧能力迁移与客户端抽查

- 按 D03 逐个迁移持续家族，区分身体动作、共享引导与独立场；保留用户授权的多友军并行。
- 补“制作范围”登记：完整原生调用、有限映射、附属原创胶合、明确不支持四类，说明玩家可观察的差异。
- 对确实改过的家族进行最小客户端与多人观察，记录未验收项；不反复重跑每个附属的完整旧矩阵。
